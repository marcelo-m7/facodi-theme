# FACODI Theme Architecture

## Boundary

`website_facodi` owns presentation only.

```text
Odoo Website / website_slides
├── routing/controllers
├── website records
├── navigation/header/footer
├── authentication
├── forms
├── course catalog/content
├── membership/progress
└── Website Builder
          │
          ▼
website_facodi
├── Website Builder palette variables
├── frontend SCSS
├── layout inheritance hooks
├── FACODI logo/favicon assets
└── eLearning visual refinements
```

The theme never becomes the source of truth for learning data and does not override access, publication or completion behavior.

## Odoo theme mechanisms used

### Primary variables

`static/src/scss/primary_variables.scss` extends Odoo's standard `$o-color-palettes`, `$o-selected-color-palettes-names` and `$o-website-values-palettes`. It is loaded through `web._assets_primary_variables` so Bootstrap/Odoo components derive their semantic colors from the Website Builder theme rather than from duplicated CSS rules.

### Frontend bundle

`theme.scss` and `elearning.scss` are loaded through `web.assets_frontend`. CSS is scoped under `.facodi-site`, which is added to the standard `#wrapwrap` through QWeb inheritance of `website.layout`.

The inheritance extends the existing dynamic `t-attf-class` attribute rather than replacing it, preserving page-specific classes generated by Odoo.

### Standard templates

No standard header/footer/course template is copied. The initial implementation relies on standard markup and stable CSS classes. QWeb inheritance is used only for the global FACODI styling hook and metadata/favicon.

## Typography and assets

The theme uses a system-font fallback stack. Font binaries are not part of this repository. The bundled SVG logo and favicon are project-owned static assets; administrators may still set the active Website logo and favicon through standard Odoo configuration.

## eLearning

`elearning.scss` styles standard `website_slides` catalog/content selectors only. It does not add controllers, models, JavaScript actions or membership/progress logic.

## Upgrade discipline

Prefer Website Builder variables and Bootstrap/Odoo utilities first. Add custom SCSS only when a FACODI-specific visual treatment cannot be represented cleanly through standard variables. Prefer QWeb/XPath inheritance to template replacement. New JavaScript requires an explicit presentation need and should use Odoo's current frontend framework rather than legacy widgets.
